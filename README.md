# 車間 SHIFT

車廠服務團隊的本機排班網站，使用 Python 標準函式庫與 SQLite，前端為原生 HTML/CSS/JavaScript。不需要 npm 安裝、雲端資料庫或網路連線。

## 啟動

先將 ZIP **完整解壓縮**至可寫入的資料夾，不要在壓縮檔內直接啟動。Windows 與 Linux 均需要 Python 3.9 以上（包含標準函式庫 SQLite）；壓縮檔不內含 Python。網站執行不需要 Node.js 或安裝 Python 套件。

### Windows

安裝 Python 後，雙擊 `start.bat`，或在解壓縮目錄的 PowerShell 執行：

```powershell
.\start.bat
# 自訂連接埠與獨立資料庫
.\start.bat --port 8877 --db "data\workshop-demo.sqlite3"
```

啟動檔會依序尋找 `py -3`、`python3`、`python` 並檢查版本與 SQLite 支援；錯誤時保留視窗方便查看。也可直接執行 `py -3 -X utf8 -B app.py`。

### Linux（macOS 亦適用）

在解壓縮目錄執行，使用 `sh` 不依賴 ZIP 解壓後是否保留執行權限：

```sh
sh start.sh
# 自訂連接埠與獨立資料庫
sh start.sh --port 8877 --db "data/workshop-demo.sqlite3"
```

若已保留執行權限，仍可使用 `./start.sh`。也可直接執行 `python3 -X utf8 -B app.py`。

### 使用與停止

開啟 http://127.0.0.1:8765 。使用期間保留終端機視窗，按 Ctrl+C 停止。連接埠已被使用時，可用 `--port` 指定其他連接埠。請讓執行程式的系統日期、時區與瀏覽器所在電腦一致。

Windows 若在 Ctrl+C 後詢問 `Terminate batch job (Y/N)?`，輸入 `Y` 並按 Enter 即可。

伺服器只綁定本機回送位址：若安裝在 Linux 遠端主機，請在該主機開啟瀏覽器，或從自己的電腦建立 SSH tunnel，例如 `ssh -L 8765:127.0.0.1:8765 user@server` 後再開啟本機網址。

資料預設保存在 `data/workshop.sqlite3`，重啟後仍保留。首次使用建立 3 位櫃檯、5 位技師、2 位現場接待，使用職務加編號作為可修改的初始姓名；首次點選「自動排班」建立當週計畫。

**本次 ZIP 包含目前的 SQLite 資料**，解壓後會沿用既有班表、人員及請假。需要全新工作區時，使用 `--db` 指向不存在的新資料庫檔案；不必刪除原資料。

## 排班規則與操作

### 教學提示

預設顯示功能旁的「?」，點選即可查看該操作的教學；手機也可直接點選，不需要滑鼠懸停。提示按鈕不會執行旁邊的排班或表單操作。

- 右上角「教學提示：開啟／關閉」可隨時關閉或重新開啟全部提示。
- 單則提示可按「×」、Esc 或點擊外部關閉，也可在提示內選擇「關閉所有教學提示」。
- 開關偏好只記錄在目前瀏覽器的 localStorage，重新整理仍保留；同一網址的其他分頁會同步。不同電腦或不同瀏覽器不共用偏好。若瀏覽器禁止儲存，開關仍可在本次頁面使用。
- 提示包含自動排班、週別、缺額、手動調班、CSV、請假、人員與規則設定。Tab 可移至提示按鈕，再按 Enter 或空白鍵開啟。

### 班表操作

- 3／5／2 解讀為**人員總數**。預設每日最低需求為櫃檯 2、技師 3、接待 1，週一至週日皆營業。
- 單班 09:00–18:00，每人每個日曆週最多出勤 5 天，每週從週一開始。人數、時間與上限可在「排班規則」調整。
- 「自動排班」以最小成本最大流求最大可覆蓋人次，在可行的解中優先平衡同職務的每週出勤，再參考前四週工作量。相同輸入可重現相同結果。
- 無請假時預設 42 人次，七天每個職務都到位。請假者絕不補進請假日，無法滿足的需求標示缺額。新增或修改人員後不會自行覆蓋班表，需點選重排。
- 點選班表中的「出勤／休息」手動切換，會驗證請假與每週上限。手動可安排高於最低需求的人力，表格會顯示實際／需求數。
- 請假以整日、起訖日期皆包含計算，登記後即生效，會移除所有涉及週別的衝突班次；取消請假不會自動恢復班次。請假管理的紀錄依選定週別篩選，可切換週別查看。
- 重排既有班表時，**今天以前的安排保留，今天起的手動安排會被取代**，操作前會提醒。首次產生一個完全空白的週，可建立完整七天計畫；這是計畫班表，不是打卡出勤紀錄。
- 停用人員會移除今天起的班次，保留歷史安排；恢復人員後可重新排班。既有人員職務固定，轉職務請停用後新增人員。
- 設定為全域規則，時間修改會影響所有週的顯示，歷史缺額也以目前需求計算。降低每週上限若與本週／未來班表衝突會阻擋，錯誤訊息列出相關人員與週別；更早的歷史班表不會阻擋。
- CSV 以 UTF-8 BOM 輸出繁體中文，每位人員列出每日出勤時間、請假／休息及出勤天數；姓名含試算表公式開頭會加上跳脫字元。

## 資料備份

停止服務後複製 `data/workshop.sqlite3` 即可備份。還原時停止服務，再以備份檔替換原檔並重新啟動。API 寫入使用 SQLite transaction 與外鍵、唯一鍵；同時請假與排班會序列化處理。

## 驗證

開發中只執行變更涉及的測試檔，收尾才執行完整套件：

```sh
python3 -X utf8 -B -m unittest tests.test_scheduler -v
python3 -X utf8 -B -m unittest tests.test_app -v
python3 -X utf8 -B -m unittest tests.test_http -v
# 完整套件
python3 -X utf8 -B -m unittest discover -s tests -v
node --check static/app.js
```

Windows 將以上 `python3` 改成 `py -3` 即可。`node --check` 是選用的開發語法檢查，不是啟動網站的必要步驟。

測試使用自動清除的獨立 SQLite 檔案；HTTP 測試會在 127.0.0.1 的臨時連接埠啟動服務。受限沙箱可能需要允許本機 socket。

## 範圍與限制

- 本機單一工作區，不含登入、權限分級、員工自助請假或核准流程。服務僅綁定 127.0.0.1，拒絕跨來源寫入與非本機 Host；不要直接暴露至區域網路或公網。
- 目前無早晚班、半日假、技能交叉支援、逐日不同需求、個別班次鎖定、版本歷程或自動備援。
- 每週上限不是跨週連續出勤上限；未計算休息時段、加班或法規規則。09:00–18:00 是排班時段，不是扣除休息後的工時計算。
- 多個分頁可同時操作，但沒有即時推播；別的分頁變更後請重新整理。
- 日期操作支援 2000-01-03 至 2099-12-27，兩端皆為完整週邊界。
